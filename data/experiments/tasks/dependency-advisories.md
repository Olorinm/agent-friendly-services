# 依赖漏洞公告：核对已有告警与修复版本

分类：开发者工具 / 依赖漏洞公告（developer-tools/dependency-advisories）

## 需求与范围

[依赖告警处理工作流](https://docs.github.com/en/code-security/how-tos/manage-security-alerts/manage-dependabot-alerts/view-dependabot-alerts)说明开发者会查看告警详情，并据此决定依赖的升级版本。[Django 维护者的安全发布说明](https://www.djangoproject.com/weblog/2025/oct/01/security-releases/)也直接要求受影响用户升级。这些官方资料支持核实告警和修复边界的实际维护需求，不证明该需求的市场频率；GitHub 的工作流资料来自候选服务商，不能当作独立用户调查。

本题使用根据真实维护者公告制作的合成依赖笔记：固定一个已装版本和两条外部告警，核对版本是否仍匹配，以及同一发布分支的修复边界。它不要求找出动态数据库中的全部漏洞、选择今天的最新安全版本、扫描代码或证明漏洞在某个应用中可利用。两个聚合服务可能共享 GitHub Advisory Database、PyPA 或维护者公告，结果一致不等于独立发现漏洞。

参考 [Terminal-Bench v4.0.0 的结果可核验与需求明确原则](https://github.com/harbor-framework/terminal-bench/blob/v4.0.0/rubrics/task-proposal.md)及[题目与验收一致性规范](https://github.com/harbor-framework/terminal-bench/blob/v4.0.0/rubrics/task-implementation.toml)，在候选调用前固定包、版本、告警及维护者参考，允许不同查询方式。只借鉴材料分离、可核验结果和无隐藏要求的做法，不照搬其高难度门槛，也不声称复现安全扫描基准。

## 冻结与独立核验

先接入，再用新会话执行业务题；保留正常安装和连接配置，清理接入问答材料。各服务使用相同任务、模型、工具和预算，无需账号的免费入口从无凭据开始。真实认证差异、限流、分页、元数据缺失及服务成本如实披露；不预写调用脚本，也不向执行者提供维护者参考快照或预期修复版本。

参考仅由候选执行前独立取得的 Django 维护者安全公告与发布记录建立。最终结论核对包、已装版本、两条告警、所属发布分支和修复边界；允许大小写、公告别名和等价版本表达。无需列全版本范围、严重度、CVSS、披露日期、固定字段名、特定文件、固定链接数量或额外日志。公告标识可通过同一真实记录的别名映射确认；候选记录缺失或空响应不能独自证明不受影响。可以由记录引用链补充维护者事实，不要求两个服务返回相同字段或相同数量的记录。

本题只能解释一次低量告警核对的接入与交付表现，不能推广为总体漏洞覆盖、独立安全发现、可利用性验证或当前推荐升级版本。维护者参考由候选之外独立取得，不代表候选的原始数据也独立于维护者；共享上游和各自正常化处理须随结果披露。
