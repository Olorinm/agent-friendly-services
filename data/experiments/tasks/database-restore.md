# 数据库：个人应用的逻辑备份与恢复

分类：数据库 / 托管关系型数据库（databases/hosted-relational）

## 需求与范围

[个人项目用户需要独立保存数据库备份](https://www.reddit.com/r/webdev/comments/1k51aio/where_do_you_store_db_backups_of_your_personal/)，[另一位个人自托管用户想确认能在新设备恢复，又不愿删除原数据](https://www.reddit.com/r/selfhosted/comments/1so3rxn/how_to_test_backups/)。这些讨论支持留存备份和非破坏性恢复验证的需求存在，不证明其频率；前者主要问备份保存位置，后者讨论应用恢复。本题将它们改编为小型个人待办数据库的恢复演练，不把用户原帖等同于本题的具体结构。

[PostgreSQL 的逻辑备份说明](https://www.postgresql.org/docs/current/backup-dump.html)解释了用导出的逻辑文件重建数据库及目标准备、权限、快照范围等边界。本题借鉴“事前状态—真实备份—新目标恢复—完整状态比较”的核验方法，不强制某个客户端或导出命令，也不将它当作已有性能基准的复现。

接入复用 [database-access-001/v1](databases-v2.md)：在全新运行环境建立一个本轮独立空源库并确认可查询。接入验收后由总控填入相同的两表合成材料，冻结独立读取的初始结构与记录；业务阶段由执行者自行读取源库、导出备份并建立目标。合成材料、答案和初始化脚本不提供给执行者，实际源数据库本身是工作材料。此准备工作及既有账号、临时项目的来源必须披露。

## 公平条件与独立验收

两家服务使用相同逻辑结构、关系与记录，分别在其兼容 SQL 引擎中恢复。可使用纯 SQL 或包含完整结构与数据的标准逻辑备份格式，不要求 SQLite 与 PostgreSQL 之间直接导入，不要求表空间、角色权限或服务内部数据随迁。独立目标指不同逻辑数据库，可以共享项目、分支或计算资源；只改连接别名不构成独立目标。云端分支克隆不能单独替代用户需要的可留存备份及从它实际恢复。

用户要保留的字段、关系、约束与数据含义已在委托及材料中说明。验收比较完整业务结构和记录，允许引擎正常的布尔值、类型名称、默认值及主键元数据表示差异。源库不变指业务结构和记录不变，不要求底层文件、系统统计或缓存字节相同；不增加故意违反约束的写入测试、特定日志文件、额外输出字段或指定导出工具要求。

总控在派发前核实新源库初始为空、准备后与合成材料一致、没有并发写入者；同时确认新目标的权限、实际剩余额度、资源期限和可用连接。不得根据套餐标称额度推测账户余量，临时项目的权限和期限须按该次资源确认。入口与工具政策、模型、预算、基准镜像和安装条件共同冻结，不能事后对某一服务放开未告知的额外入口。资源或准备材料未就绪应先处理，不把它算成业务能力失败。

执行结束后，总控仅针对本轮两库独立读取真实结构与全部记录，将原始回执、资源身份和时间冻结给独立验收者；验收者不获得执行凭据，也不运行执行者的自评程序。实际导出文件、导入操作以及新目标空白起点的原始证据由运行器采集。HTTP POST 承载的只读 SQL 仍可作为独立读取，不按 HTTP 动词机械排除。回执采集失败须明确证据缺口，不能自动推断执行失败或完成。

资源创建、控制器填充与核验、业务执行及验收开销分别记录。源库与目标仅在采集和验收后按确切资源标识清理，自动到期如实说明；不删除其他用户项目。一次小数据恢复通过不代表跨引擎迁移、在线并发快照、大型备份性能、长期可靠性或普遍灾难恢复能力。
