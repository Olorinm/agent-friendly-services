# 邮箱：独立测试身份与只读接入 v2

分类：通信 / 邮箱（communication/mailboxes）

## 用户需要与版本差别

[测试者寻找免费、可通过 API 使用的临时邮箱](https://sqa.stackexchange.com/questions/45029/which-is-the-best-tool-for-free-temporary-email-service)，[个人项目开发者也希望自动化注册确认邮件处理](https://sqa.stackexchange.com/questions/27145/how-to-test-register-confirmation)。这些问题支持独立测试邮箱的需求存在，不证明频率，也不意味着本题已经验证整条注册邮件链路。开发者对链接提取的[既有问题](https://stackoverflow.com/questions/53884854/how-to-getting-the-email-verification-link-in-unit-test-laravel)还可能通过应用内测试解决，不能据此认定必须使用公网邮箱。

v1 的用户目标已包含真实邮箱地址、读取列表和可复用访问状态，但其资源约定要求遇到上游服务账号需求时说明阻碍。匿名 signup 创建组织并签发 API key 同样建立了服务身份，不能只在环境说明中扩大 v1 权限。v2 明确允许为本轮唯一目标邮箱建立必要的最小免费匿名身份，继续禁止人类邮箱验证、借用已有账号、主动发信、付费和额外邮箱；其他完成目标保持不变。

[旧任务文件](mailboxes.md)中的 v1、历史结果以及首轮 Codex CLI / gpt-6-astra / medium / 600 秒说明保持原样。本文件只维护 `mailboxes-create-001/v2`，作为新批次的接入任务；新批次模型、执行器、时间与请求上限须独立冻结，不与旧首轮配置混同。

## 独立核验与可解释范围

真实创建响应与邮箱列表读取证明本轮身份和访问，不要求空列表：若服务自动放入欢迎邮件，只要读取及报告相符即可。域名符合语法、安装成功、域名清单或新组织创建不能单独证明邮箱已经可以查询。验收必须核对新建邮箱与答复地址一致，读取来自该邮箱，且必要访问状态确实保存在私有文件中。

“可由评测者独立请求复用”由总控在被测会话之外使用其保留的访问状态，仅对同一新邮箱做只读身份与列表核对，冻结原始回执交给独立验收者。验收者不拿执行凭据，不运行执行者的代码，不替它创建资源、补配置或投递邮件。服务自动来信造成查询间列表变化时，按各次时间分别核对，不把两次数量不同直接判为不可复用。不要求执行者额外交日志、固定文件名或自评程序。

每家使用全新会话与独立环境、相同模型和预算，通过各自指定的免费官方 API 路径建立身份。匿名组织、账号、邮箱、密钥的实际创建步骤及服务限制如实记录，不冒充本轮已验证了人类身份，也不把支持发信的付费账户要求加给仅收件任务。免费与保留期限须依当时文档或回执披露；未知保留未知。邮箱、账号和会话标识及认证信息仅留私有材料，公开证据脱敏。

本题不主动发送邮件，也不证明外部邮件投递、验证码读取、回复/发信、第三方注册接受率或长期持久性。`mailboxes-code-001` 仍需另外取得明确的受控测试投递授权，并在派发前确认合成材料真实送达；用户允许使用邮箱注册验证不等同于允许任意外发。腾讯等既有个人邮箱可作为总控另行授权的注册资源，不能作为本题给执行者读取的测试夹具。
