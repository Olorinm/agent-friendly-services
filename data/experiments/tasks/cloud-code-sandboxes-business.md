# 代码沙箱：支出分析、图片整理与表格清洗

分类：`cloud-hosting/code-sandboxes`。需求来源于 2026-10-12 打开核实；它们支持场景存在，不证明需求的市场频率。题目中的个人场景与合成材料是设计者的缩小推断，不是来源原话或来源的测试结论。

## 需求与方法

[E2B 的 CSV 分析工作流](https://changelog.e2b.dev/resources/guide-groq-js)将用户上传数据送入隔离运行环境并返回图表，支持远端代码执行、结果回传的实际工作流程，不把教程当市场频率。[Lark 的客户案例](https://changelog.e2b.dev/customers/lark-case-study)说明新环境隔离执行和取回产物的需要；这里改成个人小型材料，不继承其企业敏感数据或 Docker 特权要求。[AgentBench](https://github.com/THUDM/AgentBench)有操作系统和数据库交互环境，借鉴完成实际操作与取得最终结果的判定，不照搬难度或宣传数字。

## 远端执行证据与统一基线

代码沙箱比较必须证明分析发生在指定外部沙箱，不能只查最终文件。运行器保存远端执行请求/响应、实际程序与结果取回身份，总控独立核验绑定；验收 Agent 不拿沙箱凭据去重跑。各候选的依赖准备方式、CPU/内存、系统语言与网络权限按共同可比基线事前冻结；执行者当次安装算本次开销，下一次恢复基线。文件材料按上列确定规则生成并冻结，不含调用服务或求解程序。系统暂不支持中文字体会影响图的可用交付，但若基线漏准备或网络阻断安装须单独记录环境责任。

共用准备与验收规则见[派发前提](README.md#dispatch-prerequisites)和[任务设计角色](AGENTS.md)。本表标注的具体资源未准备好时，不进入派发队列。
