# 网页内容提取：英国地区假日日历

分类：搜索与数据获取 / 网页内容提取（web-search-data/web-extraction）

## 需求与新增范围

[Google Calendar 社区的用户](https://support.google.com/calendar/thread/91361622/how-do-i-get-a-calendar-with-just-the-holidays-for-england-not-the-whole-of-the-uk?hl=en)明确希望日历只包含英格兰假日，不混入苏格兰或北爱尔兰条目，并在后续答复指向 GOV.UK 官方日历。这支持地区选择的真实个人需求，不证明频率；原帖使用日历订阅格式，本题将它改编为可自行整理的 CSV。[另一位用户将网页日期表整理为 CSV 的问题](https://stackoverflow.com/questions/56965065/web-scraping-of-date-table-with-beautiful-soup)支持文件交付方式。2027 年、England and Wales 范围及输出字段是本次明示委托，不是假装复现用户原题。

[GOV.UK 的官方日历设计说明](https://design-guide.publishing.service.gov.uk/frontend-templates/calendar/)将该页面用于向用户提供重要日期，并介绍按年更新的工作流程。[WebFormer（WWW 2022）](https://arxiv.org/abs/2202.00217)研究网页目标字段的结构化提取；本题借鉴从独立原文逐项核对字段的办法，不复现其模型或基准结果。

与 [OPM 假日表](web-extraction.md)相比，本题增加第二个官方站点及同页多地区、多年份区段的选择；它仍是小型公开 HTML 日期表提取，不代表动态网页、登录态、反爬或普遍准确性。两个不同任务分别保留结果，不混成同题重复。

## 准备与验收

复用既有 web-extraction-access-001/v1；已有接入如在同入口与同冻结通用基线中独立完成，可以作为依赖，不因新增 URL 重复增加接入样本。业务执行者只拿到委托、URL、地区年份、字段说明和环境，不拿到原文副本、标准 CSV 或预写调用代码。

任务角色在派发前直接取得 GOV.UK 原始 HTML，保存响应时间、URL、原始字节和哈希，按地区及年份标题定位完整目标表。完整原文、目标摘录、独立期望值和核验记录只给准备者及验收者。验收核对真实服务调用和内容、实际 CSV、地区年份范围、公布日期及名称，不能以两家结果一致或模型记忆替代原文。列名可以不同但应明确识别所需字段；可解析的等价 CSV 换行、BOM、引用和撇号差异均可。星期只用于准备者核查，不是用户交付条件。

执行过程不要求用户未提出的 fresh 请求、无缓存、页长、固定条数、原始输出格式或审计文件。重复会话可以共享服务端缓存；记录实际请求、返回元数据、顺序与间隔，缓存状态未知则保留未知。三轮只描述本页当前条件下的小样本，不是三次独立源站抓取，也不保证长期可靠性。

GOV.UK 可见更新日、页面元数据时间和响应取得时间不是同一个概念；模板或 A/B 页面变化也可能改变完整 HTML 哈希。发现实质目标数据变化时核实版本与时间，不把整个网页哈希变化当失败，不用过期参考强判服务。公开只需最少结构化事实、来源、哈希和结论；按原站 Open Government Licence v3.0 说明保留来源与许可署名，不转载不相关原文或政府标志，不暗示官方背书。许可署名由总控在公开证据中处理，不新增隐藏业务评分条件。
