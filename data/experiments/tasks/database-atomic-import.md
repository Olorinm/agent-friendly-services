# 数据库：不留下半批数据的书目导入

分类：数据库 / 托管关系型数据库（databases/hosted-relational）

## 需求与方法

[一位开发者希望文件导入中任一 INSERT 失败就回滚整次导入](https://stackoverflow.com/questions/72663046/how-to-rollback-on-file-import-in-mysql)。原问题处理大文件，支持“不要留下半批数据”的需求存在，不证明其普遍性，也不是本题的小型书目材料。这里把同一目标缩小为个人应用可重复使用的导入器和两个独立测试副本，不测吞吐量。

[PostgreSQL 事务教程](https://www.postgresql.org/docs/18/tutorial-transactions.html)说明整组操作全部生效或全部撤回；[SQLite 事务说明](https://www.sqlite.org/lang_transaction.html)和[约束冲突行为](https://www.sqlite.org/lang_conflict.html)提醒，单条语句失败不自动等于此前整个事务已回滚。本题以事前固定的两表初态、实际调用与错误、事后独立完整读回共同核验，不以两个服务的输出互相当作真值，也不认证所有并发、崩溃或瞬态行为。

接入复用 [database-access-001/v1](databases-v2.md)，在本轮新环境建立一个独立空数据库并独立验收。总控随后在该库准备两个相同结构、相同初态的测试表。既有组织或父项目、免费资源与安装条件在本轮环境中披露；不提供导入实现或私有参考答案。

## 公平条件与独立验收

两家使用同样的字段含义、主键与非空约束、初始记录和两份原始文件。允许 SQLite 与 PostgreSQL 的正常类型、错误表示和客户端差异；单条原子批量 INSERT、官方原子 batch 或正确处理的显式事务均可。普通请求队列或一串自动提交不能仅因名称中有 batch 就视为整批原子操作。不强求相同命令、特定 SDK、数据库错误措辞、额外文件格式或写入顺序。

总控在执行前独立取得两个表的完整结构与初始记录；执行全部停止后，使用可信连接独立读取同一资源的完整终态与结构。运行器保存实际使用的程序、写入和执行记录及数据库错误，独立验收核对程序与实际调用的对应关系，并检查是否存在提交后的补偿删改。若该对应关系或完整执行路径无法恢复，正确终态也不能独自证明任务完成。正常事务回滚与修改已提交数据来凑结果必须区分。

验收者不获执行凭据、不调用数据库、不运行执行者交付的程序，也不修复测试数据。总控准备、独立读取及验收成本另列。此题只支持已观察到的两个小型导入样本及其实现路径，不等同于对所有未来输入、瞬态可见性、并发隔离、断电恢复或全面 ACID 的认证。
