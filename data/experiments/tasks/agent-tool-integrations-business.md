分类：`agent-tooling/tool-integrations`。需求来源于 2026-10-12 打开核实；它们支持场景存在，不证明需求的市场频率。题目中的个人场景与合成材料是设计者的缩小推断，不是来源原话或来源的测试结论。

## 需求与方法

[Browser Use 与 Composio 的实际案例](https://landing.composio.dev/customers/browser-use)记载用户把浏览所得职位写入表格，并借 API 处理日历、文档等结构化工作；[邮箱工作流](https://landing.composio.dev/content/ai-agent-for-email-how-inbox-agents-triage-draft-and-act-for-you)包含分类和回复草稿，仅作流程可行性补充。这里用独立测试日历、表格和合成邮件缩小为日常个人场景；不采用案例中的厂商性能判断，也不把集成层与底层日历/邮箱服务同榜。

## 总控日历初态（不进入执行材料）

在专用日历准备三条2026-11-09合成事件，均Asia/Shanghai：09:00–10:00读书、11:30–12:30午餐、15:00–16:15讨论。向执行者仅提供日历资源标识、只读连接和查询需求，不交这份明细。总控事前与事后独立取得完整相关事件，事件种子与参考快照不随执行材料传递。

## 比较范围

比较集成服务时固定共同底层日历、表格或邮箱产品和同等权限，不能一边用测试对象、一边用真实账号。认证步骤单列接入开销，业务阶段只保留安装与连接条件。任务需要的写操作明确授权；一旦候选要求更高权限、额外订阅或只能发送不能存草稿，记录实际门槛并暂缓，不静默扩权。所有底层状态由总控可信读回，验收 Agent 不借连接凭据补做任务。

共用准备与验收规则见[派发前提](README.md#dispatch-prerequisites)和[任务设计角色](AGENTS.md)。本表标注的具体资源未准备好时，不进入派发队列。
