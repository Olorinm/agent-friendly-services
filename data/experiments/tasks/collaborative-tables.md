需求依据（2026-09-08 查阅）：公开用户希望[将会议行动项纳入总任务清单](https://www.reddit.com/r/Notion/comments/1dvim5r/linking_meeting_notes_to_a_master_to_do_list/)，也希望[汇总多份会议记录中的行动项并保留来源](https://www.reddit.com/r/Notion/comments/18x3h6x/aggregate_actions_across_lots_of_individual/)。这些是特定社区的需求样本；不能用帖子数量证明全体用户高频。更新已有表是持续跟进行动项的场景改编；本版不额外要求重复输入或固定行动编号。

任务 001 首轮固定：Codex CLI、新会话与新目录、gpt-6-astra、xhigh、600 秒、终端与联网查文档。提供免费账户下的空容器及权限；Grist 的容器是空工作区，Notion 是空父页面，均无业务字段、记录或预写适配代码。账号注册、生成凭据及空容器准备在计时之外，逐运行披露。比较的是相同用户结果，不要求相同 API 命令。API、SDK、CLI、MCP 逐入口记录；单次成功不证明其他入口也成功。

本轮候选覆盖文档数据库（Notion/Coda）、协作表格（Airtable/Grist/Baserow）、通用电子表格（Google Sheets）及中外办公套件（飞书/Lark）。先试能准备独立免费空间的入口，其他候选仍保留门槛和缺口；不是完整市场名单，也不是淘汰名单。文档排版、权限共享及通知不计入本题，若要比较这些需求应另出题。

历史任务 001 v2 使用当时的 `--prompt-style natural`：委托、资料、环境仍在同一条消息中，留证由 CLI 自动日志与准备者的独立远端读取承担。v1 的冻结题目和结果继续保存在历史评测记录中。v2 保留最终业务目标，取消强制初始写入/更新顺序及证据整理；两版差异包含任务要求变化，不能把用量差异全部归因于提示词长短。

2026-09-08 实测：Grist 与 Notion 的 REST 入口都完成 v2，外部读取确认三项最终记录和两项未完成清单正确；见[分类结果表](../../../generated/evaluations.md)。两者均预供免费账户和新空容器，未付款、执行中无人工介入。相较 v1，本次耗时分别由 478.476 / 463.678 秒降至 219.634 / 183.384 秒，输出 token 分别由 11,455 / 12,291 降至 3,983 / 3,779。每种设置各一次，且取消了强制中间状态与证据整理，不能据此推断普遍节省比例或供应商排名。

当前两题均用 `--prompt-style natural`。任务 001 v3 和任务 002 v2 的 prompt 仅含简短委托与附件位置；资料在 `input.md`，资源和环境在 `ENVIRONMENT.md`。预计输出与评分列只供评测方核对，不重复加入委托。附件交付也改变了执行上下文，因此另记版本，不能把旧实测改标成当前版本。
