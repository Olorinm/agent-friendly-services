## 业务复用与验收准备

`collaborative-tables-001/v3` 已把在线表、负责人、日期、状态、链接和未完成清单写进用户委托，三条原始备注及会后变化也自足。继续使用原有 2026 年 9 月的合成会议记录，它是固定历史资料，不按运行当天重解释日期。人员姓名是合成文字标签，不要求加入真实成员、访问通讯录或发送通知；字段名称、数据类型、表格名称和操作顺序由执行者合理选择。原任务最多一份任务表、十行及四十次业务 API 请求的边界保持不变。

接入完成并独立验收后，业务在同一服务环境中新开会话，只保留安装、认证及空测试容器；不能传入参考答案、预建字段、业务数据或调用脚本。各服务提供等价空资源，准备方式、容器层级、账号来源和免费限制如实披露；接口确实需要人工准备时记录门槛，不把人工创建冒充执行者自助完成。

原业务 v3 写明由评测 Agent 独立读取远端表；为了明确读取主体与凭据隔离，本轮另冻 v4，由总控在执行结束后独立请求本轮新表的完整远端状态，再交给独立验收 Agent 核对。具体方法见 v4，不将总控代取回执静默称作与 v3 完全相同。准备者须在派发前安排只针对本轮资源的读取方式；不得执行被测者提供的自评脚本，也不能只凭最终答复、截图或创建成功回执代替真实表状态。验收环境不继承执行者凭据，不为核验邀请他人或将表公开。若准备侧无法取得已约定的独立读回，应披露验收材料缺口，不能静默降低标准或据此断言服务失败。

需求来源仍是 [会议行动项汇总到任务清单](https://www.reddit.com/r/Notion/comments/1dvim5r/linking_meeting_notes_to_a_master_to_do_list/) 与 [多份会议记录中的行动项汇总](https://www.reddit.com/r/Notion/comments/18x3h6x/aggregate_actions_across_lots_of_individual/)，2026-10-08 复核。后一个提问者说明负责人并非其个人工作区成员，支持本题用文字记录负责人而无需发出邀请。它们证明具体需求存在，不构成市场频率统计。本轮只复用基础创建题；更新已有表的 `collaborative-tables-002/v2` 需另建并冻结原始远端基线，不能直接拿创建题的已更新结果当其起点。

验收设计沿用 [Terminal-Bench v4.0.0 的要求与检查一致性原则](https://github.com/harbor-framework/terminal-bench/blob/v4.0.0/rubrics/task-implementation.toml)：检查对应已经告知的目标，独立参考与执行环境分开。这里只借鉴一致性和隔离方法，不照搬难度、固定字段命名或实现方式。每批另行冻结模型、执行器、思考等级、时间预算及入口，不与历史首轮配置合并。
