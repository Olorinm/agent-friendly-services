# 邮箱：需求与任务表

分类：通信 / 邮箱（communication/mailboxes）

2026-09-09 首轮收录 12 个候选，资料和未测状态由目录统一展示。

用户需要的是让 Agent 获得独立邮箱、接收注册邮件并继续工作；长期账号与临时测试有不同的保留期和隐私要求。邮箱管理与批量投递不能默认互相替代，现有 Resend 等发信服务不因名称里有 email 就自动进入本轮。

## 需求依据

- [测试者寻找可用于手工及自动化测试的临时邮箱](https://sqa.stackexchange.com/questions/45029/which-is-the-best-tool-for-free-temporary-email-service)：支持准备测试邮箱的需求。
- [开发者在验证测试中不知道如何取得邮件链接](https://stackoverflow.com/questions/53884854/how-to-getting-the-email-verification-link-in-unit-test-laravel)：支持从目标邮件提取信息的需求，不代表必须使用真实公网收件方案。
- [应用开发者希望接入 Gmail、Outlook 并处理收发邮件](https://www.reddit.com/r/SaaS/comments/192b5ng)：支持持续管理已有邮箱的需求。

以上旧问题只证明需求存在，不证明当前服务能力或市场频率。检索中大量 Agent 邮箱文章来自厂商自荐，不把它们当独立用户频率证据。本轮先测临时测试邮箱和验证码读取；长期保留、回复线程、附件与第三方网站接受率后续再测。

## 本轮条件与验收

- 使用 `gpt-6-astra / medium`、Codex CLI、自然任务输入、600 秒上限；每个服务/方式单独新会话。首轮每项一次，不能据此推断稳定性或全领域排名。
- `mailboxes-create-001` 的邮箱创建本身就是用户任务。若平台另要求注册服务账号或授权现有邮箱，仍在接入阶段单独记录；不把事先准备的账号算作 Agent 自助注册。Mail.tm 与 Guerrilla Mail 不预置上游账号。
- 评测者只读返回的访问信息，独立请求同一邮箱、核对当前收件箱。不能执行被测 Agent 的脚本来代替验收。新测试地址、账号标识、密码、会话及原始日志仅留本地，公开证据脱敏。
- 注册门槛、临时保留期与访问私密性留在服务详情；创建试跑的成绩只适用于创建任务。空收件箱读取成功不代表验证码投递、网站接受率或长期账号安全已验证。

首轮结果：2026-09-09，两个创建任务均通过独立 HTTP 重读验收。随后使用用户明确指定的 Gmail 向两个测试邮箱投递相同的三封合成邮件，均确认送达并独立执行验证码任务：Mail.tm 完成；Guerrilla Mail 读对验证码和时间，但 API 丢失主题，未满足完整交付。接入方式均为 API，各项各一次，不推广为普遍稳定性结论。具体用量和证据由结果表生成，不在此重复。
