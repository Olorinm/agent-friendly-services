## How we test

Each trial runs in a fresh session and isolated container. The tested Agent gets only the user task and service entry point, never answers or other services' results; a separate session reviews it against frozen criteria. Usage comes from runner capture and evidence carries hashes, so results can be checked and rerun. Samples are still small: these are observations, not proof of long-term reliability. [Method](./AGENTS.md)

## Latest findings

- **Web extraction (GOV.UK holiday table): Jina 3/3, Firecrawl 1/3.** Firecrawl fetched the page every time and its HTML was correct, but its Markdown placed year captions after the tables; the Agent twice read the wrong year. [Evidence](./data/experiments/evaluations/afs-20261010-johor40-web-extraction-firecrawl-uk-holidays-r3.json)
- **Test location changes outcomes.** Jina Reader was unreachable from a mainland China server because of DNS interference and was recorded as an invalid run; from an overseas server, setup and both extraction tasks completed. [Evidence](./data/experiments/evaluations/jina-extraction-access-ds41-r2.json)
- **Grist shared expenses: MCP 3/3, REST 2/3.** In the REST failure the ledger and formulas were already correct on the service, but the Agent ran out of requests before its final answer: the service worked, the delivery did not. [Evidence](./data/experiments/evaluations/afs-20261010-johor40-grist-rest-shared-expenses-r1.json)
